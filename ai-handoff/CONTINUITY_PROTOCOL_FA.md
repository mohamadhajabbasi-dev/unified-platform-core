# پروتکل دائمی استمرار پروژه برای تمام AIها

## قاعده صفر
GitHub این مخزن **مرجع حقیقت وضعیت اجرا** است، نه حافظه چت، فایل ZIP یا ادعای قبلی. قبل از هر کار `AGENTS.md`، `README.md`، `docs/MASTER_PLAN_FA.md`، `ai-handoff/PROJECT_STATE.md`، `ai-handoff/WORK_LOG.md`، `ai-handoff/NEXT_ACTIONS.md` و `ai-handoff/DECISIONS.md` را کامل مطالعه کن.

## گردش اجباری هر اقدام
1. یک Action ID یکتا تعیین کن؛ بررسی کن قبلاً همان کار انجام نشده باشد.
2. پیش از اجرا دقیقاً ثبت کن محیط، مرحله، هدف، وضعیت کنونی و فایل/جدول مقصد چیست.
3. قبل از ساخت جدول، سرویس یا فایل، فهرست موارد فعلی و کاربردشان را بررسی کن؛ اگر مرجع موجود است از همان استفاده کن.
4. روی تولید فقط پس از تأیید مالک و بکاپ/تست بازگشت اقدام کن.
5. پس از **هر اقدام** اعم از موفق/ناموفق، در WORK_LOG رکورد **append-only** بنویس: timestamp / phase / agent / task / pre-check / operations / paths / results / tests / risks / blockers / next action.
6. بلافاصله PROJECT_STATE و NEXT_ACTIONS و در صورت نیاز DECISIONS و CHANGELOG را با نتیجه واقعی هماهنگ کن.
7. فایل‌های ویرایش‌شده را در GitHub commit و SHA را از ابزار بازخوانی کن؛ در صورت شکست `NOT_PUSHED` را آشکارا گزارش بده.
8. قبل از اتمام گفتگو چک‌پوینت با آخرین commit تأییدشده، فعالیت نیمه‌کاره و دستور دقیق مرحله بعد ایجاد کن.

## اصول غیرقابل نقض
- هر تننت یک مشتری مرجع برای هر هویت تأییدشده؛ مشتری در تننت دیگر پرونده جدا دارد.
- هر کالا، سفارش، قیمت و موجودی یک مرجع قابل اتکا دارد؛ ابعاد تننتی جدا ثبت می‌شوند.
- هیچ اطلاعات خصوصی tenant A به tenant B منتقل نشود؛ تست RLS الزامی.
- هیچ AI حق ندارد به بهانه بهبود، قابلیت جدید خارج از محدوده مصوب ایجاد کند.
- رمز، داده مشتری، توکن، کلید و بکاپ تولید در GitHub ممنوع.
- مستندسازی هرگز معادل انجام واقعی migration/deployment/test نیست.
